# Configured CI is bound to an observed default-branch tip

Issue #348, implementation #354. The project collector must not attribute a previous revision's successful, failed or pending run to newer code that has not been tested.

For each public project with an explicitly configured workflow, collection first obtains the declared default branch's tip through the bounded GitHub `/repos/{owner}/{repo}/branches/{branch}` endpoint. Both branch and workflow identities remain encoded path segments. A usable tip requires the requested branch name and a full 40-hex commit SHA. No absent default branch is guessed as `main`.

The existing latest-run request remains scoped to that workflow and branch with `per_page=1` and `exclude_pull_requests=true`. Only a run whose full `head_sha` matches the captured tip may contribute passing, failing, pending or stale status. Existing conclusion and age rules remain unchanged. Mismatched or malformed revision evidence yields configured `unavailable`, with no borrowed run URL, timestamp or SHA; the board is partial. A missing run is not a failed build. Collection does not search older run history for a matching result.

## Cost and failure boundaries

This adds one request per configured project workflow. Hosted query parsing and static configuration retain their six-project cap, so those entrypoints add at most six requests per board. The low-level `GitHubClient.fetchProjects` accepts a caller-supplied list as before; its total request cost scales with that list and is not newly capped here. Unconfigured CI makes neither a branch nor a workflow request. Public repository validation precedes auxiliary lookups. Refused or missing optional branch evidence stays unavailable; existing rate-limit and upstream-availability errors retain their established error contract. No timeout, retry, token scope, status enum or dependency is changed.

The tip is a **single as-of observation**, not a transaction with GitHub or a guarantee that the branch cannot move after it was read. The collector neither invents a current result from the most recent run nor promises that sequential API reads are atomic. No branch history, names from private repositories, jobs, logs or commit contents are retained in the returned project model.

## Regression coverage

`packages/github/tests/ci-current-head.test.mjs` covers old-head success/failure/cancellation, matching status and stale controls, invalid tips/run SHAs, missing branch metadata, encoded names, optional lookup failures, bounded calls, unconfigured CI and private-repository refusal. It is registered in the ordinary GitHub gate after building its package. Existing client/terminal fixtures explicitly provide a branch tip and full run SHA instead of permitting a hidden fallback. Unconfigured fixtures still reject unexpected branch calls.

The built Worker regression in `tests/rendered-html.test.mjs` checks the actual projects API for both matched and mismatched revisions, including state, head, timestamp and board freshness. Its existing aligned-workflow fixture now expects the verified head rather than null. The generated Action is rebuilt from the same source. All normal quality checks remain required.
