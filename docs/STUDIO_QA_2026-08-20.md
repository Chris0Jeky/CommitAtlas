## Production browser evidence

The production server (`npm.cmd run start`) was tested, not a development hot-reload process.

- Landing at 1440x900: one main landmark and H1, labelled primary navigation, clean hierarchy, no
  clipping, and no horizontal overflow.
- Landing at 390x844: the navigation and glow remained contained; no element overflowed.
- Studio at 1440x900 and 390x844: two-column/one-column layouts changed at the intended breakpoint,
  controls remained readable, and no element overflowed.
- Synthetic Preview returned all five selected cards, a source-backed two-project board, and
  Markdown bound to `http://localhost:3000` only after the exact configuration succeeded.
- All four themes were exercised. Paper used `#5b5148` muted text and `#8f3c22` accent text on
  `#f1ede5`, measured at 6.62:1 and 6.34:1 respectively.
- Six projects could be configured; the Add control then disabled. A workflow named
  `ci,release:nightly.yml` round-tripped without delimiter collision.
- Blank workflows remained `Not configured`. Configured synthetic workflows exposed deterministic
  demo states without inventing health for unconfigured projects.
- Removing a project after a successful preview immediately replaced the old API board with the
  current neutral draft, changed the count, removed the stale Markdown entry, returned embed URLs
  to the placeholder origin, and asked the user to refresh. A new preview rebound the exact state.
- Repository whitespace did not drop valid actions. Allowed Docs/Download URLs appeared; arbitrary
  HTTPS, HTTP, credential-bearing, malformed, and disallowed-subdomain URLs were omitted.
- Zero-contribution days rendered with zero-height bars. Total and 28-day activity labels named
  different windows. A truncated repository response exposed no partial star total.
- Copy Markdown matched the textarea exactly. With no cards selected, the UI returned an explicit
  non-success notice.
- Live-public `octocat` without an approved contribution credential loaded public profile/projects,
  disabled but retained the Streak/Activity selections, and generated exactly Profile, Languages,
  and Projects Markdown. The notice said why those cards were omitted and guessed no value.
- Invalid and missing-account paths retained the prior profile with a bounded error message; route
  changes did not reuse its embed origin or project evidence.
- The browser console contained no warnings or errors on the final exact build.

## Accessibility limitation

Landmarks, headings, accessible names, labels, legends, the live status region, colour-independent
signal labels, reduced-motion styling, and visible focus CSS were inspected. The browser-control
layer did not reliably move focus with Tab/Space, including its documented fallback. Full sequential
keyboard traversal is therefore **not verified** and must be repeated with a real keyboard or a
driver that can prove focus movement. This remains a release check.
